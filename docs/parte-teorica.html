1. O que é uma API e como funciona o consumo de dados em tempo real

API (Application Programming Interface) é um conjunto de regras que permite que dois sistemas conversem entre si. Na web, as APIs mais comuns seguem o padrão REST: o cliente (o navegador) faz uma requisição HTTP para um endereço (endpoint), por exemplo GET https://pokeapi.co/api/v2/pokemon/25, e o servidor devolve uma resposta com um código de status (200 = sucesso, 404 = não encontrado) e os dados, normalmente no formato JSON.

Consumir dados “em tempo real” significa que a página não guarda as informações dentro do HTML: toda vez que é aberta (ou que o usuário busca, filtra ou clica em “Carregar mais”), o JavaScript faz uma nova requisição e monta a tela com a resposta que acabou de chegar. Se a API for atualizada, a página mostra o dado novo sem precisar mudar o código. Como a requisição leva algum tempo, ela é assíncrona: o navegador continua funcionando enquanto espera, e o JavaScript trata a resposta quando ela chega, por meio de Promises.

2. DOM manipulation e criação de elementos dinâmicos

O DOM (Document Object Model) é a representação do HTML em forma de árvore de objetos que o navegador cria ao carregar a página. Cada tag vira um nó que o JavaScript pode ler, alterar, criar ou remover. Manipular o DOM é o que permite que a página mude sem ser recarregada.

No projeto, o HTML possui apenas um contêiner vazio, <div id="cards-container">. Nenhum card está escrito no HTML: para cada Pokémon recebido da API, o JavaScript cria um <article> com document.createElement, preenche nome, imagem, tipos, altura, peso e status, e o insere no contêiner com appendChild. Assim, 20 Pokémon geram 20 cards, e 1 resultado de busca gera 1 card.

3. Funções utilizadas para consumir a API e montar os cards

FunçãoPara que serve no projeto
fetch(url)Faz a requisição HTTP para a PokéAPI e retorna uma Promise com a resposta.
.then()Executa um código quando a Promise é resolvida, encadeando etapas: resposta → JSON → criação dos cards.
response.ok / .json()Verifica se o status foi de sucesso (200–299) e converte o corpo da resposta em objeto JavaScript.
.catch()Trata erros (sem internet, Pokémon inexistente/404) e exibe uma mensagem amigável.
Promise.all()Dispara os detalhes de vários Pokémon em paralelo e espera todos terminarem.
document.createElement()Cria um novo elemento HTML na memória (article, h3, img, span…).
appendChild() / append()Insere o elemento criado dentro de outro; append aceita vários de uma vez.
textContent, className, srcDefinem o texto, as classes CSS e a imagem de cada elemento.
addEventListener()Liga ações do usuário (buscar, filtrar, favoritar, carregar mais) às funções.
localStorageGuarda no navegador a lista de favoritos (♥), que permanece após recarregar a página.
function fetchJSON(url) {
  return fetch(url).then((response) => {
    if (!response.ok) throw new Error(`Erro ${response.status}`);
    return response.json();
  });
}

fetchJSON("https://pokeapi.co/api/v2/pokemon?limit=20&offset=0")
  .then((data) => Promise.all(data.results.map((p) => fetchJSON(p.url))))
  .then((lista) => lista.forEach((pokemon) => {
    const card = document.createElement("article");   // cria o card
    const nome = document.createElement("h3");
    nome.textContent = pokemon.name;
    card.appendChild(nome);                            // monta o card
    cardsContainer.appendChild(card);                  // coloca na página
  }))
  .catch((erro) => console.error(erro));

4. Motivo da escolha da API

O tema do trabalho são desenhos de sucesso dos anos 90 e 2000. O anime Pokémon estreou em 1997 no Japão e em 1999 no Brasil, marcou toda uma geração e continua em exibição, o que encaixa perfeitamente no tema. A PokéAPI foi escolhida por ser gratuita, não exigir cadastro nem chave de acesso, ter documentação clara e ser estável. Além disso, ela oferece imagens oficiais e dados ricos (tipos, altura, peso e atributos de batalha) que deixam os cards mais completos e permitem recursos extras como busca, filtro por tipo e paginação.

5. Regras de acesso e documentação da PokéAPI

  • Documentação: https://pokeapi.co/docs/v2. URL base: https://pokeapi.co/api/v2/.
  • Autenticação: nenhuma. Não há token nem chave de API. A API é somente leitura (apenas requisições GET).
  • Limite de requisições: não há limite fixo desde a migração para hospedagem estática, mas a política de uso justo pede que o desenvolvedor faça cache local e evite requisições desnecessárias. Abusos podem levar a bloqueio de IP. Por isso o projeto carrega 20 Pokémon por vez e as imagens usam loading="lazy".
  • CORS: liberado (Access-Control-Allow-Origin: *), permitindo o consumo direto pelo navegador.
  • Endpoints usados: /pokemon?limit=20&offset=0 (lista paginada), /pokemon/{nome ou id} (detalhes), /type e /type/{tipo} (filtro por tipo).
  • Estrutura da resposta: a lista retorna { count, next, previous, results: [{ name, url }] }; para cada item, o projeto busca a url de detalhes, que traz id, name, height (decímetros), weight (hectogramas), types[], stats[] e sprites (a imagem usada é sprites.other["official-artwork"].front_default).
